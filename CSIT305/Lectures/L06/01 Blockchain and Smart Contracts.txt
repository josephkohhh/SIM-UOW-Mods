Lecture 6 - Blockchain and Smart Contracts

What is Blockchain?
A blockchain is a distributed ledger that stores transactions 
across a network of computers. Transactions are grouped into blocks, 
which are linked together using cryptographic hashes.

Distributed Ledger: A shared digital database that is stored and 
maintained across multiple computers in a network, 
rather than on a single central server.

Computer A (Node) ──┐
Computer B (Node) ──├── Blockchain Network
Computer C (Node) ──┤
Computer D (Node) ──┘

- If 1 node is down, other active nodes still have the records 
- If all node down, blockchain is down temp and wont accept any new transc


Key Characteristics
Decentralized: No single authority controls the blockchain.
Shared Ledger: All participants have access to the same transaction records.
Immutable: Once a transaction is recorded and confirmed, it cannot be altered.

Genesis Block
The Genesis Block is the first block in every blockchain.
- Starts the blockchain.
- Generates the first unique hash.
- Serves as the foundation for all subsequent blocks.

What Does Each Block Contain?
- Transaction data
- Timestamp
- Previous block's hash
- Its own hash


What is a Hash?
Its a unique digital fingerprint generated by a hash funct 
(typically producing a 256-bit output).
- a tiny change in the data results in a completely different hash
- verify data integrity and detect tampering


How Hashes Secure the Blockchain?
If someone modifies a transaction in Block 1:
- Block 1's hash changes.
- Block 2's stored previous hash no longer matches Block 1's new hash.
- Block 3 and all subsequent blocks also become invalid.
- Blockchain detect unauthorized changes and reject the tampered chain


Blockchain Transaction Process
Step 1: User creates transaction (send a bitcoin)
Step 2: Transaction is digitally signed
Step 3: Broadcast to blockchain network
Step 4: Nodes validate transaction
Step 5: Valid transactions grouped into a block
Step 6: Consensus reached
Step 7: Block added permanently
Step 8: Ledger updated on every node

Consensus Mechanisms

1. Proof of Work (PoW)

Bitcoin 

Miners solve mathematical puzzles, first solution wins, 
add blocks and receives award (bitcoins)
- very secure (immutable)
- but network is very slow and consume alot of energy

2. Proof of Stake (PoS)

Ethereum

Validators lock up ETH (staking), ETH choose validators to validate blocks,
successfully validation receives rewards (ETH) 
- network is faster and more energy efficient 
- requires staking ETH

Smart Contract
It is a program stored in blockchain and auto execute 
when predefined conditions are met 

Features of a Smart Contract
- Self-executing
- Autonomous
- Transparent
- Immutable
- No third-party required

Ex. Self-executing digital agreement
- if predefined conditions are met, money is xferred
- no banks needed, no lawyer, etc


How to Build a Smart Contract
Step 1: Parties create legal agreement
Step 2: Define every possible condition (Delivery, Payment, Deadlines)
Step 3: Code the Smart Contract using Solidity prog lang
Step 4: Upload code to blockchain
Step 5: Execute (Contract executes automatically)
Step 6: Recording (Completed transaction stored permanently on blockchain)

Advantages of Smart Contract
- Automatic execution
- No intermediaries (banks, lawyers)
- Reliable
- Immutable
- Transparent
- Faster transactions

Disadvantages of Smart Contract
- Vulnerable to hacking
- Coding bugs, errors 

Smart Contract Apps
- Cryptocurrency Payments
- Immutable Voting Systems
