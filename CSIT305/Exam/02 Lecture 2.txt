Q1. Explain MINDIST and its role in best-first kNN search. (5 marks)

MINDIST(q, R) is the minimum possible distance between a query point q and a bounding rectangle R. 
It is computed dimension by dimension: for each axis, if q's coordinate is less than R's lower bound, 
use the lower bound; if greater than R's upper bound, use the upper bound; otherwise use q's own coordinate 
(distance contribution = 0 on that axis). If q lies inside R, MINDIST = 0.

In best-first kNN search, MINDIST is used as the priority key in a min-priority queue: the root is enqueued first,
 and at each step the node with the smallest MINDIST is dequeued (most promising branch explored first). 
 Internal nodes are expanded by computing MINDIST for each child and re-enqueuing them; leaf objects 
 are checked with actual distance and used to update the current k-nearest list. The search can safely terminate 
 once k results are found and the head of the queue has a MINDIST greater than the current k-th best distance, 
 because no unexplored node can contain a closer point — this pruning is what makes the algorithm efficient (better than O(n) naive scan).



Q2. What is a Minimum Bounding Rectangle (MBR), and how does an R-tree use it to organize spatial data? (5 marks)

An MBR is the smallest axis-aligned rectangle that fully encloses a set of spatial objects. 
The R-tree is a balanced, height-uniform tree where each leaf entry stores an object (or its MBR) with a pointer to the 
actual data record, and each internal node stores the MBR that bounds all the MBRs of its children, together with pointers to those children.

Each node has a maximum capacity f and a minimum occupancy (usually f/2). 
When inserting a new object, the tree chooses the subtree whose MBR requires the least enlargement to include the new object, 
recursing down to a leaf. If inserting causes a node to exceed capacity f, the node is split into two, 
and the split can propagate upward, potentially increasing the tree's height. Because MBRs of sibling nodes can overlap 
(unlike a Quad-tree's disjoint regions), a query may need to search multiple branches, 
but the R-tree adapts well to skewed/non-uniform data since it groups nearby objects rather than partitioning space by fixed geometry.


Q3. Describe the structure of the Inverted R-tree (IR-tree) and how it supports spatial-textual queries. (5 marks)

The IR-tree combines an R-tree (for spatial indexing) with an inverted file (for textual indexing). 
Each object has both a location and a set of text/keywords. Every node of the R-tree — leaf and internal — is augmented with 
a summary of the text content of the objects in its subtree, typically stored as a small inverted list mapping each term to the 
maximum relevance weight found in that subtree (e.g., "Sushi → <R1,5>" means somewhere under R1 there is an object with weight 5 for "Sushi").

For a query with a location and keywords, the search descends the tree using a spatial-textual score combining a spatial term S(o,q) 
and a textual term T(o,q), weighted by a preference parameter α: α·S(o,q) + (1-α)·T(o,q). 
Best-first search proceeds exactly like spatial-only kNN, except MINDIST is replaced by a minScore upper bound computed from the 
node's MBR (for the spatial part) and its inverted-list summary (for the textual part), allowing branches that cannot contain a 
high-scoring result to be pruned early.


Q4. Define Term Frequency (TF) and Cosine Similarity, and compute an example. (5 marks)

TF measures how often a term appears in a document relative to the document's total term count: 
TF(t) = (count of t in document) / (total terms in document). Example: Document "apple banana apple" → TF("apple") = 2/3 ≈ 0.67, 
TF("banana") = 1/3 ≈ 0.33.

Cosine similarity measures how similar two documents are by computing the cosine of the angle between their TF vectors: 
cos(θ) = (A·B) / (‖A‖‖B‖). Example: Doc1 = [0.67, 0.33], Doc2 = [0.33, 0.67]. A·B = (0.67×0.33) + (0.33×0.67) ≈ 0.221 + 0.221 = 0.442 ‖A‖ 
= ‖B‖ ≈ √(0.67² + 0.33²) ≈ 0.747 cos(θ) ≈ 0.442 / (0.747×0.747) ≈ 0.442/0.558 ≈ 0.79

A value close to 1 indicates high similarity in term distribution; the two example documents are quite similar since they share the 
same two terms in reversed proportions.


Q5. Define the clustering coefficient of a node and compute it for a small example. (5 marks)

The clustering coefficient Cᵢ of node i measures what fraction of node i's neighbours are themselves connected to each other. 
If node i has degree kᵢ and there are eᵢ edges among its neighbours, then:

Cᵢ = 2eᵢ / (kᵢ(kᵢ − 1)), where Cᵢ ∈ [0,1]

Example: node B has degree kB = 2 and eB = 1 edge between its two neighbours → CB = 2(1)/(2×1) = 1 
(its neighbours are fully connected). Node D has degree kD = 4 with eD = 2 edges among its neighbours → CD = 2(2)/(4×3) = 4/12 = 1/3. 
The average clustering coefficient of a graph is the mean of Cᵢ over all nodes, giving a global measure of how "cliquish" or tightly-knit 
the network is (e.g., average C = 0.33 in the lecture example).


Q6. Distinguish between a strongly connected and a weakly connected directed graph. (5 marks)

A directed graph is strongly connected if there is a directed path from every node to every other node and back again 
(i.e., for any pair A, B there exists both an A→B path and a B→A path following edge directions).

A directed graph is weakly connected if it is connected only when edge directions are ignored — that is, treating all edges as undirected, 
there is a path between every pair of nodes, but this may not hold when direction is respected. For example, a graph can be weakly 
connected but not strongly connected if some node F has no directed path back to another node G, even though an undirected path exists. 
Strong connectivity is a stronger (more restrictive) condition than weak connectivity.


Q7. Both Quadtrees and R-trees may experience performance degradation under certain data distributions. 
Explain the underlying reasons for this issue and propose appropriate mitigation strategies for each case. (10 marks)


Quad-tree:

Reason for degradation: A Quad-tree partitions space geometrically into four equal quadrants regardless of where data points actually lie. 
Under skewed/clustered data distributions, most points fall into one small quadrant, forcing repeated subdivision of that region to keep leaf capacity under threshold. 
This produces an unbalanced, very deep tree in the dense area while other branches stay shallow — query and update costs degrade toward O(n) in the worst case, and the fixed fanout=4 partitioning 
wastes many empty nodes in sparse regions.

Mitigation: Use adaptive/PR quad-tree variants that only subdivide regions with data (already partly assumed), or switch to a data-driven partitioning structure such as the R-tree or a KD-tree, which split based on actual object distribution rather than fixed geometric midpoints. Bucket-based quad-trees with larger leaf capacity, or dynamically merging sparse siblings, also reduce unnecessary depth.

R-tree:

Reason for degradation: Because R-tree nodes are built bottom-up from overlapping MBRs, when objects are dense/skewed or have highly varying sizes/aspect ratios, sibling MBRs can overlap heavily. 
This overlap means a single window/range/kNN query may have to traverse multiple branches to be sure it hasn't missed an object, increasing filtering cost and negating the benefit of the tree structure
(worst case approaches scanning most nodes).

Mitigation: Use insertion/splitting heuristics that minimize overlap and coverage area (e.g., R*-tree's forced reinsertion and 
combined optimization of overlap, area and margin) rather than the basic R-tree's "least enlargement" rule. 
Bulk-loading the tree from sorted/clustered data (e.g., Hilbert R-tree, STR bulk loading) up front, instead of incremental insertion, also produces tighter, 
less overlapping bounding boxes for skewed static datasets.


Q8. Compare the Linear Threshold Model and the Independent Cascade Model for information/influence propagation in networks. (10 marks)

Answer:

Linear Threshold Model (node-centric):

Each node v has a random threshold θᵥ ~ Uniform[0,1], representing how much peer influence is needed to activate it.
Each neighbour w of v has an influence weight bᵥ,w, and node v becomes active once the total (weighted) influence from its already-active neighbours reaches or exceeds θᵥ.
Activation depends cumulatively on how many/how much of a node's neighbours are active — a "tipping point" model.

Independent Cascade Model (edge-centric):

Starts with a seed set S of active nodes.
Each directed edge (v, w) has an independent activation probability p.
When v first becomes active, it gets exactly one chance to activate each inactive out-neighbour w, succeeding with probability p (each edge fires at most once).
Propagation proceeds in discrete time steps; the order in which simultaneously-active nodes attempt activation does not matter (memoryless, edge-independent trials).

Key differences:

Aspect	Linear Threshold	Independent Cascade
Trigger	Cumulative weighted influence vs. threshold	Independent probabilistic trial per edge
Randomness source	Random node threshold	Random edge success
Determinism given thresholds	Deterministic given θ values	Stochastic even for fixed graph
Natural analogy	Peer-pressure/tipping-point adoption	Word-of-mouth/epidemic-style spreading

Both models are used to simulate cascades for the Influence Maximization problem — choosing a seed set of size k to maximize expected spread — but they make different structural assumptions about how influence accumulates.


Q9. Explain the Influence Maximization problem, including why the "expected" cascade size is used rather than a single cascade outcome, and outline a general approach to selecting the seed set. (10 marks)

Problem definition: Given a directed graph G = (V, E) representing a social network and a budget k > 0, Influence Maximization asks: 
which set S of k "seed" nodes, if initially activated, will maximize the number of nodes ultimately influenced (activated) through the 
network, possibly over multiple propagation steps? This models applications like viral marketing — finding a small set of influential 
customers ("Kates") whose endorsement spreads a product through their social connections at minimal cost.

Why "expected" cascade size: Propagation models such as Independent Cascade are inherently stochastic — each edge activates with only 
some probability p, so a single simulation starting from the same seed set S can produce very different final influenced sets Xₛ 
each time it is run (a random realization). A single run is not representative, so the objective function f(S) is defined as the 
expected cascade size: the average size of the influenced set over many random realizations (or in closed form, the expectation over the 
random process). This gives a stable, comparable measure of a seed set's true influence potential rather than relying on one lucky/unlucky 
outcome.

General approach to seed selection:

Formulate f(S) = expected number of nodes activated when S is the seed set, under a chosen propagation model (Linear Threshold or Independent Cascade).
The problem is combinatorial (choosing the best k-subset out of |V| nodes) and f is generally monotone and submodular (diminishing returns as more seeds are added), 
which justifies a greedy algorithm: repeatedly add the node that gives the largest marginal increase in expected influence, until k seeds are chosen.
Because f(S) has no simple closed form for realistic graphs, it is typically estimated by Monte Carlo simulation — running the cascade model many times for 
a candidate seed set and averaging the resulting spread — before applying the greedy selection.

This greedy, simulation-based approach provides a provable approximation guarantee (within 1 − 1/e of optimal) while remaining computationally tractable compared to exhaustive search over all possible seed sets.
